# Companion V3：程序认知内核

> 第一开发原则（从今天起约束所有改动）：
> **程序思考，大模型表达。**
> 认知程序决定说什么，大模型只负责怎么说。程序判定回答 A 而非 B，模型不得改成 C。

本文件回答四件事：现在的决定权错在哪、双核心契约长什么样、七系统怎么从现有代码迁过去、先动哪一刀。
所有结论都对着真实代码和真实库验证过，不是纸面架构。

## 一、先把话说死：现在不是架构不够，是决定权放错了位置

我对真实库 `data/companion.db` 做了一次只读探针（`tools/probe_cognition_now.py`），三处实证：

| 证据 | 真实输出 | 意味着什么 |
|---|---|---|
| 身份卡 | `{assistant: "小智", user: ""}` | 它根本不知道自己是谁的对话对象，用户姓名为空 |
| 画像 | `称呼：改名叫小志或小智` | 那次"给我改名"被记成了"他的称呼"，身份串号的源头 |
| 召回事实 | `我问的是我是谁？` / `我在问我是谁` | 事实库是**问句仓库**，记的是"他说过这句话"，不是"他是谁" |
| 意图 | `我是谁？` → `chat`，同时 → `web_search` | 身份问题被判成闲聊，然后真去搜"我" |

再看代码，问题比数据更根上：

1. `brain/services/pipeline.py:733` 调用
   `prompt.build(persona, bundle, emotion, text, history, plan=cognitive_plan)`
   **参数里没有 `decision`。** 认知层算出的结论，在进提示词之前就断掉了。
2. `brain/cognitive/decision.py:48-58` 产出的"选项"是
   `推进目标：X` / `先接住当下情绪，不急着推进`。
   这是**元层面策略描述**，不是"这一轮要说的内容"。它无法被"表达"，只能被"参考"。
3. `brain/cognitive/verifier.py:127-145` 的校验规则是：
   模型只要不改 `options` 的个数和 id，**`summary`/`cost` 可以随便重写**。
   也就是说：程序给骨架，模型改措辞——分工正好反了。
4. `brain/tools/__init__.py:33-35` 的 web_search 触发词包含 `是谁 / 是什么 / 怎么样`。
   一个万能词压过身份、人格、记忆全部规则。

一句话概括：**现在的"大脑"是一个负责写开场说明的秘书，真正拍板的是那个 2B 模型。**

## 二、双核心契约：这是全项目的宪法

分工不靠"约定"，靠一个**不可被下游改写的数据结构**。这一层定了，后面才不会反复。

### 2.1 认知程序交出什么

```python
ContentPlan(
    speech_act    = "identity_user"        # 这是哪一类话（程序定）
    points        = ("他是正在和我交流的用户",
                     "他还没明确告诉过我他的名字")   # 语义要点，不是措辞
    claims        = (Claim("user","name",None,UNKNOWN), ...)  # 带证据与确定性
    must_include  = ("用户",)              # 渲染必须出现的
    must_not      = ("小智",)              # 渲染绝对不许出现的（防串号）
    tone          = "neutral"
    max_chars     = 80
    template_key  = "identity_user_unknown"
    actions       = ()                     # 要动的工具，权限由程序签发
    evidence      = (Evidence(...), ...)   # 每条结论从哪来
    uncertainty   = UNKNOWN                # 整轮确定性（取最弱一环）
    next_step     = "只说这两点，不许用自己的名字填进去"
)
```

字段不多，但每个都在管一件事：**points 管语义，must_* 管边界，evidence 管出处，uncertainty 管口气。**

### 2.2 语言模型只拿到什么

模型拿到的不是原对话，而是**表达任务**：

```
你不是在重新回答问题，你是在把下面这段意思说出来。
意思不能变，事实不能加，名字不能换。只允许调整语气、语序、长度。
必须表达：…
必须出现：…
绝对不许出现：…
长度：不超过 80 字。
```

这条边界有个直接好处：模型即使再笨，也没有"重新审题"的机会。

### 2.3 三条硬规矩（违反即回退）

| 规矩 | 落地方式 | 违反时 |
|---|---|---|
| 模型不得改主张、必含项、禁含项 | `kernel/check.py` 机械校验 | 重生成一次，再不合格 → 回退模板 |
| 表达失败不许"糊一句" | 模板优先，模板一定能兜住结构性问题 | 用 `fallback_text`，不许自由发挥 |
| 行动权限只由认知层签发 | `ContentPlan.actions[].permission` | 语言层无权发起任何工具 |

**还有一条我加的**：结构性问题（身份、回忆、澄清、拒绝）**默认根本不用模型**。
模板能说准的事，为什么要赌一个 2B 模型的措辞？这不是保守，这是省延迟、省错率。

## 四、程序到底怎么思考：五种机制的实际实现

原则：**每种机制都要有数据结构、有算法、有失败语义**。做不到这三样，就不算机制，只能算口号。

### 4.1 演绎：规则引擎（已实现，19 项测试覆盖）

```python
Rule(id, when=(("query_target","user"),("intent","identity"),("user_name_known",False)),
     then={"speech_act":"identity_user","template_key":"identity_user_unknown"},
     priority=30, note="问的是他，但姓名无据——只说角色，不编名字")
```

- 匹配：`when` 全满足即命中（合取，无析取）。
- 冲突消解：按 `(priority, 条件数)` 降序取第一条；**同优先级出现互斥结论时不挑边，直接标 `conflict`**。
- 复杂度：O(规则数)，当前 14 条，单轮 <0.1ms。
- 失败语义：无规则命中 → 落到 `answer` 默认档，事件里写明"没有规则命中"。

这条机制最容易被低估。它的价值不是"聪明"，是**可回退**：规则写错改一行，不用重训模型。

### 4.2 归纳：从历史算先验，不猜

- 数据源：`turn_logs`（这轮说了什么）+ `feedback`（他认不认）+ `deliveries.verdict`（卡片对不对）。
- 统计量：每个 `(intent, speech_act)` 的胜率，拉普拉斯平滑
  `p = (success + α) / (n + 2α)`，`α = 1`。
- **冷启动纪律**：`n < 5` 时不使用统计值，一律用规则先验。样本不够就装作有经验，是自欺。
- 失败语义：统计读不到 → 退回规则，事件里标 `induction:skipped`。

### 4.3 类比：先找像的，再决定要不要用

- 案例签名：`intent + 归一化实体 + 结构标记（是否问句/是否带指代）`。
- 检索：`neural/activation.py` 的二跳传播（沿 `synapses` 真实边）+ 双字重合兜底。
- 阈值：相似度 < 0.45 **不联想**。宁可答"这我没印象"，也不要硬扯一段旧事。
- 输出：只作为 `Claim` 的 `INFERRED` 证据，永远不能升到 `CERTAIN`。

这是"我记得你上次说过显卡"和"我瞎编你上次说过显卡"的分界线。

### 4.4 因果：只在有两条以上证据时才说"因为"

- 数据结构：`CausalEdge(cause, effect, confidence, evidence_count, last_seen)`，落 `beliefs` 表扩展。
- 推理：前向链（A→B→C）+ 反事实检验（移除 A，看 B 是否还有别的支持）。
- 输出约束：`evidence_count >= 2` 才允许说因果；只有一条时说"可能是"。
- 失败语义：无因果边 → 明确说"看不出因果，只有先后"。

技术排查场景里这条最有用：蓝屏是不是驱动导致的，要有两条独立证据才下结论。

### 4.5 规划：目标分解 + 有界搜索

- 目标分解：`goals` 表已有 title/status，补 `parent_id` 支持子目标。
- 搜索：A*，代价 = `轮次 + 工具延迟 + 风险系数`，启发式 = 剩余子目标数。
- 边界：深度 ≤ 3 层，候选 ≤ 5 个，总预算 ≤ 10ms。超限返回"信息不够，需要先问一句"。
- 输出：候选列表进 `reasoning/evaluation.py` 打分，**不是直接选第一个**。

### 4.6 不确定性：五档，取最弱

```python
CERTAIN    # 他明确说过 / 系统硬事实（如注入的当天日期）
SUPPORTED  # 多条独立证据一致
INFERRED   # 规则或类比推出，未被直接证实
CONFLICT   # 证据互相矛盾，必须先澄清
UNKNOWN    # 无法判断（没证据，不是"没有"）
```

整轮确定性 = 所有主张里**最弱**的那一档。
这条不做，就会出现"某个环节是猜的，整句说得像真的"——这正是现在错答的来源。

## 五、认知评价器：怎么打分、怎么学、怎么防自欺

这是你上一版没提、但决定"会不会越用越聪明"的部分。

### 5.1 打分

```
score = 0.35*目标匹配 + 0.20*成本 + 0.20*风险 + 0.15*用户偏好 + 0.10*证据强度
```

- 每个分项都必须是**可计算**的：目标匹配 = 与 goal title 的词重合度；成本 = 轮次+工具延迟；风险 = 该动作的历史失败率；用户偏好 = 他显式说过的禁忌命中数；证据强度 = 证据 trust 加权。
- 选 `argmax`，同时记录**所有候选的分数**（`evaluation_results` 表已有）。
- 没有候选就返回"信息不够"，不许默认选第一个。

### 5.2 学什么、不学什么

只有四类**可验证信号**算 reward：

1. 用户点了"不对"（`feedback`）
2. 同一问题连续复述（说明上一轮没答到）
3. 工具返回 `ok=False`（真没办成）
4. 必含项校验通过/失败（`check`）

**模型自评不算。** 这条必须写死：让模型给自己的表现打分，是最容易产生"我以为我进步了"的路径。

### 5.3 更新规则

- 指数滑动平均：`w ← w + η*(reward - baseline)*feature`，`η = 0.05`。
- 只在 `n >= 10` 时更新；单次事件不改权重。
- 每次更新写 `evaluation_results`，带 `before_score/after_score/decision`。
- 权重回退：连续 3 个窗口 `after_score < before_score` → 自动回滚到上一版本。

### 5.4 这个闭环的边界

它能做到的是：**同类任务反复做，选方案的水平提高**。
它做不到的是：无中生有的创造力。不要把"会学习"说成"会思考"。

## 六、脑图怎么亮：只有真跑过才亮

现状（`web/brain.js:398`）已经做对了一半：点亮靠真实事件、扩散沿真实 `synapses`。
但 `decision` / `appraisal` / `goal_hit` 没接进 `regionOf`，所以"它在权衡什么"在画布上根本看不见。

迁移后的事件规范：

| 字段 | 含义 | 铁律 |
|---|---|---|
| `system` | 哪个系统 | 必须是七个之一 |
| `action` | 干了什么 | 动词，不用"处理中" |
| `because` | 因为哪条证据/规则 | **空字符串一律不准写这条事件** |
| `sources` | 可点亮的真实节点 id | 没有就不亮，不画装饰 |
| `region` | 对应脑区（0-7） | 与 `regionOf` 对齐 |

真实输出示例（`tools/kernel_demo.py` 实跑，"我是谁？"）：

```
1. [perception] parse          因为 说话人=user；代词 我→user、你→assistant；命中=我是谁
2. [memory]     identity_lookup 因为 assistant:小智；user:未知       点亮 identity:assistant_name, identity:user_name
3. [memory]     fact_recall     因为 召回 1 条陈述，挡下 4 条问句/碎句
4. [judge]      rule_infer      因为 命中规则 id_user_unknown（问的是他，但姓名无据）  点亮 rule:id_user_unknown
5. [judge]      decide          因为 speech_act=identity_user，确定性=unknown
6. [express]    render_template  因为 模板 identity_user_unknown 可覆盖这一档
7. [express]    verify          因为 通过
8. [express]    emit            因为 最终由 template 产出，校验通过
```

八步全部可核。点开第 4 步能看见命中的是哪条规则、规则原文写的什么。
这才是"看到它怎么思考"，而不是看一段模型编的内心独白。

## 七、迁移路线：四期，每期都能回退

我不同意"一次把七个系统建全"。V2.5 的教训就是模块建齐了、接线没接上。
**按"一条垂直切片先通，再横向铺开"** 走。

| 期 | 内容 | 验收（看真实对话，不看单测） | 开关 | 工作量 |
|---|---|---|---|---|
| **P0（已完成）** | `brain/kernel/` 最小切片：契约 + 感知 + 身份 + 规则 + 决策 + 模板 + 校验 + 事件 | 19 项自测全绿；真实库 6 句全部答对；`我是谁` 零模型调用 | 不接生产 | — |
| **P1 止血接线** | pipeline 在 `prompt.build` 前插入 `kernel.run_turn`；身份/回忆类**短路不调模型**；工具改由 `plan.actions` 决定；prompt 瘦身到 600 字 | 20 句身份类 10/10 答对；`我是谁` 永不联网；闲聊 ≤3 句 | `kernel_enabled` | 1 天 |
| **P2 事实形状** | 写入陈述化（subject/predicate/object）；问句只进对话记录；身份卡每轮必带；profile 那条"改名叫小智"纠正 | 新写 100 条里问句占比 <5%；换说法问同一件事能召回同一批 | `fact_extract_enabled` | 2 天 |
| **P3 推理与评价** | `planning` / `causal` / `association` 接入 deep 档；`evaluation` 打分 + 事后回填 | 复杂问题能看到候选与分数；用户点"不对"能改变下一次选择 | `deep_reasoning_enabled` | 3 天 |
| **P4 学习与生长** | 权重更新 + 策略候选/启用/回滚 | 同一类错误连续 3 次后，第 4 次不再犯 | `learning_enabled` | 2 天 |

每期都必须有 **影子模式**：`kernel_shadow=1` 时只计算、不接管输出，把 `ContentPlan` 和 `check` 结果写进 `cognitive_trace`，跟旧回答并排对比一周。对比不达标就不切。

## 九、我现在对你的方案的三个不同意见

这是这份文档里最该被读的一段。

**1. 七个系统不能平行开工。**
你列的七系统是对的，但如果同时铺，会精确复现 V2.5 的结局：每个模块都能跑，谁也不决定结果。
必须**先用一条垂直切片把所有层串通**（身份/事实类问题），证明"决策 → 表达 → 校验"这条链是通的，再横向补系统。
现在这条切片通了（19 项测试），可以开始横向了。

**2. 学习系统必须排在最后，而且要带刹车。**
在评价信号不可靠的时候上线学习，不是在变聪明，是在**放大错误**。
现在"答错了还被当成历史喂回去、连说三遍"就是活证据——那套反馈回路已经在"学习"，学的是错的。
所以 P4 放最后，且必须满足两个前提：可验证信号接上了、权重能回滚。

**3. "大模型只负责怎么说"要补一句：模型说不好的时候，不许它硬说。**
2B 模型在忠实渲染上也会走形。所以不是"信任模型表达"，而是：
**模板优先 → 模型表达 → 机械校验 → 不合格回退模板**。
你已经想到"重新生成或直接用模板"，我把它做成了默认路径，而不是异常处理。

## 十、边界：这套东西是什么，不是什么

**是**：一套由程序算法和持续状态驱动的任务认知系统。它的规划、权衡、决策有明确输入输出，每个结论可追溯到证据，换掉大模型不影响认知核心运行。

**不是**：人的主观意识。规则引擎不会因为规则多就产生"我"。
"会思考"在这里的定义是**可验证的推理链**，不是拟人表演。用表演替代智能，是我们最该防的一件事。
